# What Objective-C methods are visible in standalone Mach-O files?

Target: all **3,363** physical Mach-O files in the three cataloged system images of the official iPhone 11 iOS 26.0.1 (`23A355`) IPSW, SHA-256 `2773217713e94b81fbbaa6ecb6b7e87fb176f58f5edefdb868d8d71ec6547bd2`. The [file inventory](Standalone-MachO-Coverage.md) distinguishes these files from logical dyld-cache images.

An exact-file `ipsw class-dump --re -V` pass found **847,771 Objective-C method entries**, **67,881 rendered classes**, and **3,594 categories**. All 3,363 files were inspected: 3,029 returned a parsable class dump and 334 returned the explicit `macho does not contain objc info` diagnostic. Among the parsable files, 626 yielded zero method entries. The other 2,403 have at least one method. No method entry in this pass had an unavailable selector label. These numbers describe metadata emitted by this tool for this build; they are not an exhaustive list of callable functions or methods in Swift and C++.

The collector checked each mounted file's size and complete SHA-256 against the previously published standalone inventory. For a parsable dump, it checked the Mach-O UUID against the inventory, located the file's `__TEXT` load-command range, and required every reported method implementation address to fall inside that range. Class and category metadata addresses were checked against non-`__LINKEDIT` segments. It also checked table-of-contents counts, unique class/category group labels, method-to-group counts, selector syntax, and zero-result status. The full raw class-dump output and resumable per-file checkpoints remain in an ignored local work directory; the public catalog contains only derived metadata and hashes of the command output.

The [Standalone Mach-O explorer](https://xnu.app/ios-atlas/#macho) shows method and class counts for each physical file. Selecting **Browse Objective-C methods** loads one of 64 compressed site buckets and provides local search over class, category, selector, and implementation address. A zero result means the class dump has no indexed ObjC methods, or the tool explicitly reported no ObjC metadata. It does not show that a file has no code, no Swift methods, no C++ methods, or no callable entry points. Static addresses do not show which process loaded a file or whether a method ran.

The aggregate source catalog is [`standalone-objc-methods.json.gz`](../../catalog/ios/23A355/standalone-objc-methods.json.gz). To regenerate it with the exact mounted images:

`python3 tools/catalog_standalone_objc_methods.py --macho-catalog catalog/ios/23A355/standalone-macho.json.gz --filesystem-root .local/mount-fs --systemos-root .local/mount-sys --appos-root .local/mount-app --workdir .local/standalone-objc-work --output catalog/ios/23A355/standalone-objc-methods.json.gz --workers 4`
