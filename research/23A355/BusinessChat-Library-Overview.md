# What does the BusinessChat cache image expose?

Target: the iPhone 11 iOS 26.0.1 build `23A355` iOS dyld cache, UUID `C0A7E671-35E1-3E6C-842D-FCE4E0A08C7E`. The exact BusinessChat image is `/System/Library/Frameworks/BusinessChat.framework/BusinessChat`, UUID `7682AB26-7957-39CA-B847-062728936E02`. The intact main cache has SHA-256 `6097e3ce9e29cfccd19d5aab182d006868a93a14c3a5cebcb22b6675c1527b19`; the full 80-file iOS cache family was separately matched against this phone by device-side SHA-256. The static evidence below does not establish that a process loaded this image.

## First-pass role

The [exact-image method catalog](../../catalog/ios/23A355/objc-image-methods-7682AB26-7957-39CA-B847-062728936E02.json.gz) records **270 Objective-C methods** across **34 classes and one category**. Named classes include `BCChatButton`, `BCWebViewController`, `BCMessage`, `BCMessageInfo`, `BCAuthenticationManager`, and several `BCOAuth2*` request and response types. The [symbol catalog](../../catalog/ios/23A355/ios-cache-symbols.json.gz) records 316 named `__text` symbols. The [load-command catalog](../../catalog/ios/23A355/dyld-dependencies.json) records 17 direct library loads, including BusinessChatService, Accounts, UIKit, WebKit, AuthKit, and Security. These names and declarations suggest a business-chat user interface and an authentication path; they do not prove a complete workflow.

An `ipsw dyld extract` derivative of this exact cache image has SHA-256 `4cfd1b7be0564417aa9dafbd14c3639698cec4651fa4107c9f872ec0af1ab636`. Its file hash is an **analysis derivative**, not the device's cache hash. Hopper through REA recovered `-[BCChatButton setup]` at `0x234d181a8`. The pseudocode references localized `CHAT_BUTTON_DOUBLE_LINE_*` and accessibility-label keys, a `MessagesIcon` image, fonts, subviews, and `updateAppearanceForState:`. This supports the narrow inference that the class builds a chat button UI. It does not establish where the button appears or whether it appeared on this phone.

The same image names `-[BCAuthenticationManager fetchTokenWithRequest:completion:]` at `0x234d1ad8c`, `processQueryItems:completion:` at `0x234d1b3dc`, and `exchangeCode:completion:` at `0x234d1b604`. The inspected `fetchTokenWithRequest:completion:` pseudocode reads the request URL and its query items and conditionally calls `processQueryItems:completion:`. This supports an authentication-flow hypothesis. The inspected portion does not prove an outgoing network request, a successful token exchange, or runtime use.

## Evidence and next questions

The local REA evidence bundle is kept outside Git at `.local/rea/businesschat-evidence.json`. Relevant retained IDs are `ev_5c22b7ba3bd8f6e69e60c112ac6a4ae4b2bcce420c73f20c8fdc36258c72a62c` (class labels), `ev_2dd8e1872a8c451a7c82ede688f9d2a2e392ccc1f2bd44e69faf18a49470bd` (chat-button methods), `ev_6157f44f054c528f22e7777214331dc5364a35519826b6303bee84b167744a4c` (button setup pseudocode), and `ev_de6deb2fe7bcc016fdc20c4f321e07fd53ee3122ed05b865e5ed86b7cde1a6f9` (token-request pseudocode). REA used Hopper for the focused analysis; Ghidra's class-label query failed with a 2 GB Java heap limit and contributed no negative finding.

Reproduce the derivative with `ipsw dyld extract <MAIN_DSC> /System/Library/Frameworks/BusinessChat.framework/BusinessChat --output <PRIVATE_DIR> --slide --objc --stubs --cache <MAIN_DSC>.a2s`, then check its SHA-256 and the addresses above. The [acquisition record](../../docs/acquisition-23A355.md) identifies the complete cache family and firmware source. Next work is to follow `BCChatAction` and `BCNetworkProvider` call sites, identify which process loads the image, and confirm any proposed hook point on the device before treating it as a tweak target.
