# Are all published Mach-O-like device files accounted for?

For the current iPhone 11 iOS 26.0.1 (`23A355`) snapshot, the reviewed public file-format catalog labels **3,623** regular files `Mach-O / mixed`. An exact path-set reconciliation assigns **3,117** to firmware standalone files matched by device-side SHA-256, **463** to acquired and device-hash-verified jailbreak binaries, and **42** to acquired and device-hash-verified Developer binaries. The sets do not overlap. The remaining **one** path is `/rootfs/System/Library/Frameworks/QuartzCore.framework/default.metallib`, the mixed Metal container whose bytes were separately matched to the exact FileSystem image. Thus every **3,623 / 3,623** public Mach-O-like path has a verified ordinary-binary identity or this explicit mixed-container exception.

The [site builder](../../tools/build_site.py) now requires exact equality between the public `Mach-O / mixed` path set and those four evidence groups. It rejects a missing or extra candidate instead of silently showing an unanalysed file. The four source indexes are the [file-format catalog](../../catalog/ios/23A355/live-file-formats.json.gz), [live standalone identity](../../catalog/ios/23A355/standalone-live-identity.json.gz), [jailbreak Mach-O](../../catalog/ios/23A355/jailbreak-macho.json.gz), and [Developer Mach-O](../../catalog/ios/23A355/developer-macho.json.gz). The mixed container is described in the [base-root type note](Base-Root-Code-Coverage.md).

This is a **public, reachable path-set result**, not a complete inventory of all possible executable code on the phone. The private Data and Mobile data views have additional byte-verified candidates and 73 inaccessible directories; their paths are not published. A `file` signature does not detect code embedded in every archive or asset, or generated at runtime. The one withheld randomized jailbreak filename is outside the published path set. Static Mach-O metadata does not establish runtime loading or safe hook points.
