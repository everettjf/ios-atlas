# What code did the live base filesystem type pass find?

Target: the connected iPhone 11 (`iPhone12,1`) on iOS 26.0.1 (`23A355`). On 2026-11-06 UTC, a read-only `file-5.43` pass classified all **219,216 reachable regular files** in the completed base `/rootfs` mount view. The NUL-delimited result had exactly the same unique path set as the earlier private mount snapshot. The command exited successfully with no stderr. Its private output has SHA-256 `488594c6195f1a7b74d6ab59d63b78cd726f73bb7586d06c362e526f2cc475f4`; the private snapshot manifest has SHA-256 `3c5a83cce583c6e42173dc1b10202b9e7c74f2952719fcd8cc87d3b78e0e419d`. Neither private file is published.

The type descriptions identify **3,118 Mach-O or universal-binary candidates**. **3,117** are ordinary standalone Mach-O files already [byte-matched to this phone and the exact FileSystem firmware image](../../catalog/ios/23A355/standalone-live-identity.json.gz). No additional ordinary Mach-O file appeared in this complete path set. The remaining candidate is the mixed QuartzCore Metal container at the logical path `/System/Library/Frameworks/QuartzCore.framework/default.metallib`. Its **6,643,552** bytes were acquired read-only and matched a separate device-side SHA-256 result. A read-only mount of the official FileSystem image gave the same SHA-256, `4dabd416a12e58ea4c2eb9cfa42399569b0b8d4931c6b12f67ff0639bfd762b7`; the [Preboot observation](Preboot-Metal-Container.md) and official SystemOS image also match those bytes. The official IPSW SHA-256 is `2773217713e94b81fbbaa6ecb6b7e87fb176f58f5edefdb868d8d71ec6547bd2`.

`file` prefixes one matched candidate, `/bin/ps`, with `setuid Mach-O`, so a type filter that checks only whether the description begins with `Mach-O` misses it. The candidate check accepted descriptions containing `Mach-O` or `universal binary`, then reconciled the exact path set with the 3,117 independently hash-verified files. The mixed Metal container has a `MTLB` slice and a Mach-O `gpu_executable` slice; it is outside the ordinary standalone Mach-O count.

## Reproduce and limits

With the saved, pinned root SSH route to the exact phone, run `find /rootfs -xdev -type f -exec file -0 -0 -- {} +` and keep the output under ignored `.local`. Parse the NUL-delimited path/type pairs, reject duplicate paths, and compare their set with the completed private base-mount scan. Select type descriptions containing `Mach-O` or `universal binary`, then reconcile exact device paths with the verified standalone identity catalog. Hash the one remaining candidate on the device before acquiring it privately; compare its local hash with the mounted official FileSystem file. Unmount the image after inspection.

This is a complete **file-type pass over reachable regular files in one mount view**, not a complete inventory of executable behavior. `file` can miss scripts, encrypted or embedded code, and formats it does not recognize. The 3,117 Mach-O pages reuse exact-file firmware static metadata; they do not establish runtime loading. The base mount and the separate Preboot and jailbreak views may overlap, and the two partial data-volume views still have inaccessible descendants. See [mount coverage](../../catalog/ios/23A355/live-coverage.json) and the [collection procedure](../../docs/live-device-collection.md).
